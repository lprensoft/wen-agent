# 外源插件

[← 插件总览](README.md)　·　[← 文档首页](../README.md)　·　中文　·　[English](../en/plugins/external.md)

这一节里的东西与其它插件不同：`bundles` 是内置的管理入口，而它下面那些 `ext_` 开头的卡片，是你自己装进来的插件包，装几个就有几张。

外源插件走 [Agent Plugins 1.0](https://agent-plugins.org/) 标准——2026 年 8 月由 OpenAI、微软、AWS、Cursor 与 Vercel 联合发布的插件包格式，ChatGPT、Codex CLI、Cursor、GitHub Copilot、VS Code 共用同一批插件包。一个包是一个目录，根下有 `plugin.json`，可以带 `skills/`（技能手册）与 `mcp.json`（MCP server 声明），**不含任何可执行代码**。命令行的完整用法见[命令行](../cli.md#wen-plugins装外源插件包)。

## `bundles`：安装入口

| 配置项 | 默认 | 说明 |
|---|---|---|
| `source` | 空 | 要安装的插件包：本机上的一个目录或 `.zip` 路径 |
| `update_name` | 空 | 要绑定或解除更新来源的已安装包名 |
| `update_url` | 空 | 发布者的 HTTPS `update.json` 地址 |
| `update_key` | 空 | 发布者 Base64 编码的 Ed25519 公钥 |
| `auto_check` | 开 | 自动检查更新，只验签清单，不自动安装 |
| `check_hours` | 24 | 检查间隔，1–720 小时 |

四个操作：**安装**、**重新握手全部**、**绑定更新源**与**解除绑定**。安装会连一次包里的 MCP server 取工具清单；换更新地址或公钥前要先解除绑定，有待应用更新时先取消。

`source` 只认**服务所在机器上的路径**——浏览器里的文件传不过去。远程部署时先把包传到那台机器上，再填路径。卸载没有做进界面，用命令行：`wen plugins uninstall <名称>`。

这个插件不给模型任何东西：不注入提示词，也不提供工具。

## `ext_*`：装进来的插件包

每个装好的包在设置页上占一张卡片，名字是 `ext_` 加包名（插件名全局唯一且会被拼成目录名，一个叫 `memory` 的包否则会与内置的记忆插件撞名）。卡片可以单独开关，关掉它，这个包带的技能与工具就都不生效。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `confirm` | 关 | 调用前确认。外源工具能做什么由对方决定，拿不准时先开着 |
| `max_result_bytes` | 16384 | 单次结果最多保留的字节数，超出截断 |

操作按包的内容与更新状态出现：**重新握手**只连这一个包；绑定来源后有**检查更新**与**更新**，暂存后显示**取消待更新**。只有技能的包也能检查与更新。

**装完与卸完都要重启服务**：插件在启动期一次性注册，注册顺序还承载着提示词的拼接顺序。

### 技能

包里 `skills/` 下的每个子目录是一篇技能手册，与你自己写的技能进**同一份清单**、共用同一个 `read_skill`。它们要等 [`skills`](memory.md) 插件打开之后才会进清单——它默认是关的。

### MCP 工具

包里 `mcp.json` 声明的 server 提供的工具进入模型的工具表，工具名的形状是 `<包名>_<server 名>_<工具名>`。支持 stdio（本机子进程）、Streamable HTTP 与已废弃的 HTTP+SSE 三种传输。

**工具清单在安装时取一次并存下来**，不是每次启动现问——插件在注册时就要交出工具清单（程序要查全局重名），在那一步为每台 server 起一个子进程握手，会让服务每次启动都停上好几秒。包更新了、依赖后来才装好、上次没连上，用「重新握手」重取。

子进程按需拉起：装完之后没人调用的话，一个进程都不会起。

每台 server 都会拿到标准规定的两个环境变量：`PLUGIN_ROOT` 指向包目录，`PLUGIN_DATA` 指向 `plugins/<插件名>/data/`。后者跨卸载重装保留——server 攒在里面的索引与缓存不该跟着包一起消失。

### 也认别家的插件包

Claude、Codex、Cursor 的插件包格式比 Agent Plugins 出现得早，社区里已经有很多。它们的清单在 `.claude-plugin/plugin.json` 这类位置、没有 `$schema`，但内容的固定位置是一样的，因此也认——**只读得懂里面的技能与 MCP 声明**，那些格式特有的东西（命令、子代理、钩子）不会生效，装的时候会说明一句。

## 签名更新

更新来源不猜 `repository` 或 `homepage`。先手工安装一个版本，再在 `bundles` 卡片填包名、更新清单 URL 与发布者公钥并绑定；也可以完全走命令行：

```bash
wen plugins track pdf-tools https://example.com/pdf-tools/update.json <Base64-公钥>
wen plugins check pdf-tools          # 省略包名则检查全部来源
wen plugins update pdf-tools         # 人工确认，暂存已验签候选
wen plugins update pdf-tools --cancel
wen plugins untrack pdf-tools
```

`info` 会显示来源、公钥指纹、上次检查、候选与待重启状态。服务正在运行时，上述会写状态的命令行操作拒绝执行，请改用设置页，避免两个进程同时写更新状态。

### 发布者要提供什么

任意静态 HTTPS 托管都可以，GitHub Release 也能用来放 ZIP。每个包一份清单和一份 detached signature：

```text
https://example.com/pdf-tools/update.json
https://example.com/pdf-tools/update.json.sig
```

```json
{
  "schema_version": 1,
  "name": "pdf-tools",
  "version": "1.3.0",
  "archive_url": "https://example.com/releases/pdf-tools-1.3.0.zip",
  "sha256": "<ZIP 的 64 位小写十六进制 SHA256>"
}
```

- 签名算法是 Ed25519；`.sig` 是 Base64 编码的 64 字节签名，签名输入是 `update.json` 的**原始响应字节**，不是解析后重新序列化的 JSON。公钥是 Base64 编码的 32 字节公钥，经独立可信渠道交给用户。
- ZIP 可以放在另一域名下：地址与摘要都已被签名。清单、签名与下载只走 HTTPS，重定向也不能降级到 HTTP；URL 不带用户信息或片段。
- 清单包名、ZIP 内 `plugin.json` 的包名与已安装包必须一致，ZIP 内版本也必须等于签名版本。ZIP 下载与解包各有 64 MiB 上限，解包最多 5000 个文件。
- 版本必须能按 `vX.Y.Z`（`v` 可省）及现有预发布规则比较。缺版本或无法识别的版本不参与自动检查；同版与降级不会作为更新，也没有强制降级入口。

### 检查、暂存与重启的边界

后台默认每天只下载清单和签名，用绑定的公钥验签并记录候选。**不下载 ZIP、不替换包、不握手、不重启。** 启动后有两分钟宽限，失败至少一小时再试；一个来源失败不影响其他来源。

点「更新」或运行 `wen plugins update` 才会下载候选指定的 ZIP，复核签名、摘要、包名、版本与目录安全后完整暂存。按钮 token 绑定的是界面上看到的候选；另一个窗口换了候选，旧按钮会被拒绝。暂存期间当前包和工具缓存不变；下一次真正启动服务时才切换，切换前还会核对当前包内容没有在暂存后被改动，失败恢复旧包。

更新保留 `PLUGIN_DATA`、插件开关与工具配置，**不会自动执行新包里的 MCP 命令**。只有技能的包重启一次即可；带 MCP 的包在新版应用后需要人工「重新握手」，再重启一次让新工具清单注册。暂存后未重启前可以取消。

绑定公钥只认证**之后的更新**，不反向证明此前手工安装的包来自这个发布者。SHA256 只保证 ZIP 与签名清单一致，发布者身份来自你固定的公钥。换 URL 或公钥要先解除绑定再重新绑定，不做在线自动换钥。

备份包含更新来源与公钥（URL 可能含私有部署信息），不包含 pending、暂存或回滚目录，因此恢复备份不会带回半完成更新。

## 安全

装一个插件包意味着**将来会在你的机器上执行它声明的命令**，取工具清单那一步当场就会执行一次。命令原文在安装时会打出来给你看。命令行里可以用 `--no-connect` 先装不连。

压缩包里指向外部的路径（`../`）与符号链接一律拒绝；解包有大小与文件数上限；插件包里的每一条路径都必须落在包目录之内。校验在复制之前完成，装一个坏包不会在配置目录里留下残骸。

`mcp.json` 里直接写着 `Authorization`、`Cookie` 这类头时会提醒一句：插件包是拿来分发的，写在里面的凭据等于公开的凭据。提醒而不拦——那是包作者的选择。
