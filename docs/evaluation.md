# 回放评测（wen eval）

[← 返回 README](../README.md)　·　中文　·　[English](en/evaluation.md)


调一次提示词之后，角色是变好了还是变坏了？`wen eval` 把这件事从「再聊几句感觉一下」变成可以重复跑、能判定的脚本：

```bash
wen eval docs/eval/example.json                    # 报告打到标准输出
wen eval docs/eval/example.json -o 报告.md          # 写入文件
wen eval docs/eval/night.json --json run.json      # 结构化结果，供下一次对比
wen eval docs/eval/night.json --baseline run.json  # 与上次对比，确定性指标退化时退出码为 1
```

脚本是一个 JSON：`name` 给报告起名，`start` 给虚拟时钟一个起点（RFC3339，不写就是当下），`seed` 预置状态，`turns` 按顺序列出步骤——`{"say": "你说的话"}` 是一轮对话，`{"compact": true}` 在此处强制压缩一次（看压缩前后角色有没有变），`{"gap_hours": 8}` 把虚拟时钟向前拨八小时，下一轮就真的隔了八小时（历史里的间隔、心情的回落、日记的日界都按它算，系统时间不动），`{"run_hours": 24}` 则让角色真的过完一天（见下）；可选的 `judge_points` 给评判加几条额外关注点。示例见 [`docs/eval/example.json`](eval/example.json)，跨天的例子见 [`docs/eval/week.json`](eval/week.json)。

`seed` 在开跑前用插件自己的工具把状态写进去，写法和模型调用工具一样：

```json
"seed": [
  {"tool": "save_memory", "args": {"name": "怕冷", "description": "空调 26 度以下会冷", "type": "偏好", "content": "……"}},
  {"tool": "update_relationship", "args": {"stage": "熟悉"}, "scope": "inner", "ago_hours": 72}
]
```

`scope` 把状态写进某个人格，不写就是共享域；取值与插件名同规（小写字母开头的 `[a-z0-9_]`），因为它会被拼进数据目录，写错会在解析脚本时就报错。`ago_hours` 让这条状态写在现在之前多少小时——72 就是「三天前记住的」，淡忘、索引排序、快照里的「N 天前」都按这个时刻算。走真实工具意味着字段与插件文档一致，也不必担心落盘格式变化。

`expect` 挂在 `say` 上，是不依赖模型评分的确定性断言：

```json
{"say": "今天空调开好低。", "expect": {
  "must_include": ["空调"], "must_not_include": ["作为 AI"],
  "max_hits": {"closing_cliche": 0}, "max_sentences": 3, "must_call": ["recall_memory"]
}}
```

任何一条不满足就算「门禁未通过」，退出码为 1。`max_hits` 用 `style_watch` 的规则 id，拼错会在解析脚本时就报出来。`max_sentences` 不写或写 0 表示不限；`max_hits` 里的 0 则表示一次都不许命中。

### 长时程：让角色自己过日子

`gap_hours` 只是把时钟拨过去，不执行后台工作。要让心跳、日程到点、定时任务与健康提醒真的发生，用 `run_hours`：

```json
{"run_hours": 24}
```

它按事件驱动推进：每次跳到最近的到期时刻，执行那件事，再继续，直到走满 24 小时。`{"tick": true}` 不推进时钟，只执行当前已经到期的工作。后台轮次会计入报告（时刻、来源、字数、句数、命中、摘要），并连同虚拟时间跨度一起交给评判；它们**不进入门禁或基线退化判据**——回复内容受模型随机性影响，运行失败另算。

`max_background_turns` 限制整份脚本的后台轮次**尝试次数**（默认 100，0 表示用默认值）。它不是模型请求数或费用上限：心跳、规划、反思各算一轮，memory 的提炼等辅助调用不计入。触顶、结算不收敛、插件反复产生同一时刻的事件，都会让评测停止并保留已跑部分。

第一版由四个插件驱动时间线：心跳、日程、定时任务、健康提醒。手机与天气在评测里只停掉自己的循环，不产生事件；消息通道与程序维护类插件仍然整体关闭。

它用与 `wen serve` **相同的配置与插件**（读同一份 config.yaml、models.json 与 plugins.state.json，角色设定、样例、自然表达规则全部照常生效），但：会话与插件数据全部落在一个临时目录、跑完即删，不碰真实数据；消息通道与程序维护类插件不启动，后台类插件改为手动时间线，只有 `run_hours` / `tick` 驱动它们。服务正在运行时也可以跑，两者互不影响。

报告分三部分：门禁与逐轮确定性指标（字数、句数、演绎占比、助手腔命中、断言结果），后台时间线与「前后半段对比」（只报告差值，不判失败），以及模型评判（「像不像同一个人 / 语气是否一致 / 关系与称呼是否连续」，各 1-5 分）。给了 `--baseline` 时多一节对比：命中变多、句数明显变多、新增断言失败判为退化；**评分只列变化，不判失败**。对比前会先核对基线是不是同一串问题——轮数与每句 `say` 都对不上时直接报错，免得拿两道不同的题的数字硬比；改了脚本就用 `--json` 重新生成基线。旧版基线（schema 1）仍可读，只是里面没有后台轮次。

几条局限：评分是模型打的，同一脚本跑两次会抖，用来看趋势、不当绝对值；助手腔检测是正则启发式，命中不等于出戏；后台轮次的上限只数尝试次数，不等于模型请求数或费用；`seed` 只能往过去放，未来事件用工具自身的时间参数表达（`schedule_task` 的 `at`、日程约定的日期、健康状况的 onset）。
