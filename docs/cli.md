# 命令行

[← 返回 README](../README.md)　·　中文　·　[English](en/cli.md)

## 子命令

```
wen                        启动服务（等价于 wen serve）
wen serve [-c 配置] [-p 端口]  启动服务
wen config [栏目] [-c 配置]    引导式修改配置（栏目：plugins / models / server）
wen plugins [子命令] [-c 配置]  管理外源插件包（list / install / uninstall / info）
wen status [-c 配置]           打印当前配置与运行状态
wen eval <脚本.json> [-o 文件]  回放一段脚本对话，生成文风与角色一致性报告
wen update [--check] [-y]  检查并安装新版本
wen version                打印版本号
wen help [命令]            显示帮助
```

## wen config：在终端里改插件配置

`wen config` 是给**远程部署**准备的：插件的开关与参数不进 config.yaml，此前只能在 Web UI 上改，而远程机器上的 Web UI 未必方便打开。它有两种模式，进去后会在界面顶部标明：

| 服务状态 | 模式 | 行为 |
|---|---|---|
| 正在运行 | 在线 | 经服务的接口修改，**改动立即生效**，不必重启 |
| 未运行 | 离线 | 直接改配置文件，下次启动生效 |

之所以在服务运行时必须走接口：插件状态文件由服务端从内存全量重写，外部改动既不会生效，还会在服务端下一次写入时被整个抹掉。判定依据是配置目录下的 `wen.lock`（记录着实际监听地址），并实际连一次确认——进程被强杀留下的陈旧记录不会造成误判。

离线模式下插件**只登记不初始化**：读配置项声明、改开关与参数都不需要它们真的跑起来，而照常初始化会把各条消息通道的长连接、心跳与定时任务一并拉起来——用户只是想改个参数。

表单由插件自己声明的配置项生成，与设置页同源，因此新增插件时两边同时就有了配置界面。插件声明的操作也在这里：选中微信通道会出现「扫码绑定」，二维码直接以字符画在终端里（黑白不随终端配色，深色主题也能扫），码下附链接原文兜底，过期自动刷新重绘——远程服务器上不必再为扫码打开 Web UI。


## wen plugins：装外源插件包

外源插件走 [Agent Plugins 1.0](https://agent-plugins.org/) 标准：一个插件包是一个目录，根下有 `plugin.json`，可以带 `skills/`（技能手册）与 `mcp.json`（MCP server 声明）。Claude、Codex、Cursor 那三种格式的包也认，只读得懂里面的技能与 MCP 声明。这份标准由 OpenAI、微软、AWS、Cursor 与 Vercel 在 2026 年 8 月联合发布，ChatGPT、Codex CLI、Cursor、GitHub Copilot、VS Code 等客户端共用同一批插件包。它不含任何可执行代码，因此与宿主用什么语言写无关。

```bash
wen plugins list                   # 看装了哪些
wen plugins install ./pdf-tools    # 从目录装
wen plugins install ./pdf-tools.zip
wen plugins install ./x --no-connect   # 装但先不连接里面的 MCP server
wen plugins refresh pdf-tools      # 重连一次，把工具清单重取一遍
wen plugins info pdf-tools
wen plugins uninstall pdf-tools
```

装好的包放在配置目录的 `bundles/<插件包名>/`，在设置页上各占一张卡片、归入[外源插件](plugins/external.md)一节，可以单独开关。设置页上也能装：那一节的 `bundles` 卡片里填路径、点「安装」，与这里的命令等价（只认服务所在机器上的路径）。插件名前面加了 `ext_` 前缀：插件名全局唯一且会被拼成持久化目录，一个叫 `memory` 的包否则会与内置的记忆插件撞名。

### 技能

包里 `skills/` 下的每个子目录是一篇技能手册，与你自己写的技能进**同一份清单**、共用同一个 `read_skill`。它们要等「技能手册」插件打开之后才会进清单——它默认是关的，装的时候命令行会提醒一句。

### MCP server

包里 `mcp.json` 声明的 server 会被拉起来，它们提供的工具进入模型的工具表。三种传输都支持：**stdio**（本机子进程）、**Streamable HTTP**，以及已废弃的 **HTTP+SSE**。非回环地址必须用 HTTPS。

工具名的形状是 `<包名>_<server 名>_<工具名>`：工具名在本程序里是全局唯一的，而两个包各带一台叫 `fs` 的 server 是完全正常的事。

**工具清单在安装时取一次并存下来**，不是每次启动现问。因为插件在注册时就要交出工具清单（程序要查全局重名），在那一步为每台 server 起一个子进程握手，会让服务每次启动都停上好几秒。包更新了、依赖后来才装好、上次没连上，用 `wen plugins refresh <名称>` 或设置页上的「重新握手」按钮重取。

**子进程按需拉起**：装完之后没人调用的话，一个进程都不会起。连接断了（server 自己崩了、机器睡过一觉）下次调用会自动重连一次。

每个包有两个配置项：**调用前确认**（默认关；开着时每次调用先问一句，无人值守的轮次没有可确认的人，按拒绝处理）与**单次结果最多保留**（默认 16 KiB；远端返回多少由对方决定，而它会原样进入上下文并计入压缩判据）。

每台 server 都会拿到标准规定的两个环境变量：`PLUGIN_ROOT` 指向包目录，`PLUGIN_DATA` 指向 `plugins/<插件名>/data/`。后者跨卸载重装保留——server 攒在里面的索引与缓存不该跟着包一起消失。`mcp.json` 里的 `args`、`env` 的值与 `cwd` 支持 `${PLUGIN_ROOT}` 与 `${PLUGIN_DATA}` 两个占位符。

### 几条边界

**装完与卸完都要重启服务**：插件在启动期一次性注册，注册顺序还承载着提示词的拼接顺序。服务正在运行时命令行会提醒。

**安装会在本机执行插件包里声明的命令**（取工具清单那一步）。命令原文会先打出来给你看。不想连就加 `--no-connect`，之后再 `wen plugins refresh`。

压缩包里指向外部的路径（`../`）与符号链接一律拒绝；解包有大小与文件数上限；插件包里的每一条路径都必须落在包目录之内。校验在复制之前完成，装一个坏包不会在配置目录里留下残骸。一台 server 写坏了只跳过它，同一个包里其余的照常。
