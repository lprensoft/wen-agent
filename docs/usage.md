# 用量与预算

[← 文档首页](README.md)　·　[← 返回项目 README](../README.md)　·　中文　·　[English](en/usage.md)

花了多少、花在哪儿、要不要设个上限——三件事分别由账本、价格表与预算设置回答。它们记的都是**这台机器上这个程序自己发出的请求**，不是提供商的账单：同一把密钥在别处用的量不在这里，金额也只是按你填的单价估算。

## 账本：每次调用一行

配置目录下的 `usage/` 里一天一个分片（`YYYY-MM-DD.jsonl`），一行一次调用，只追加、从不覆盖。判据只有一条：**这次调用有没有收到实测用量**——收到就记，哪怕随后流式请求报错，甚至接下来又切了备用模型（失败的那笔与成功的那笔各记一条）；没收到（有些兼容实现成功回复却不带 usage）就不落行，也不计入请求数与预算已用量：

- 时间、写入时的当地日期、类型（对话、压缩或辅助调用）与发起方（空表示网页前台；插件发起的记插件名；核心自己的非交互辅助调用记 `internal`）。
- 提供商、模型，以及输入、输出、缓存命中与缓存写入 token。
- 心跳、定时任务这类**后台轮次同样入账**——「没人看着时花了多少」正是最容易漏掉的一笔。
- 不含模型试连（设置页上的一次显式探测）与嵌入调用（那条接口不返回用量）。

账本是旁路数据，但几种「账本出问题」的后果不同。**启动时**目录写不进去：服务照常启动，预算进入降级、**一律放行**——数字不可信时拦比不拦更糟——它在一次成功记账或一次成功重扫之后恢复拦截。**启动时第一次扫描就失败**（本月历史没读全）是另一档：一次成功记账不足以恢复，历史还缺着，得等整月重扫成功；重试最早在距上次扫描 30 秒之后，由接下来的预算判定或状态查询触发，没有后台定时器。**运行中**某一笔追加失败：那一笔仍计入已用、照常拦，只是账本缺这一行——这件事只有运行中的服务知道，它会在网页与 IM 的状态、用量页预算栏和 `GET /api/usage` 里标「账本写入失败、合计可能不全」；`wen usage` / `wen status` 从磁盘重新统计，发现不了从未落盘的一笔，合计可能偏低且不会告警。手工删掉某一天的文件，那天就不算——它是纯文本 JSONL，可以随时离线聚合。

`wen eval` 把整场落盘搬进临时目录，评测期间的调用不会混进真实账本。

## 价格：把 token 折成钱

单价填在**模型**上（设置页 → 模型 → 某个模型），按每百万 token 计，分输入价、输出价、缓存读价与缓存写价四项；缓存两项留空时按输入价估算，报告与预算里会注明「估算」。四项全留空表示不为这个模型定价，它的用量计入「未定价 tokens」——**未定价不等于免费**，这部分不会按 0 元算进金额。

价格带币种（最多 8 个字符，不区分大小写）。不同币种不做汇率折算，报表里并列，预算只累计你设定的那一种。

账本只存 token，金额是查询时按**当前**价格表现算的：

- 改价之后，同一个月的旧记录也会按新价重算——想保留旧账，改价前先把那一月的报告记下来。
- 在设置页保存模型配置时，本月预算立即按新价重扫，不必等到下个月才发现上限的真实位置。

## 预算：到限之后

预算设置存成配置目录下的 `usage.json`，设置页 → 用量 → 月度预算保存的就是它：

| 字段 | 含义 |
|---|---|
| `monthly_tokens` | 每月 token 上限，0 表示不设限 |
| `monthly_cost` | 每月金额上限，0 表示不设限；需要价格表才生效 |
| `currency` | 金额上限的记账币种（默认 `CNY`） |
| `warn_percent` | 已用达到上限的这个百分比时提醒（默认 80），只提醒不拦 |
| `over` | 到限之后：`skip_background`（默认，暂停后台任务、前台照常）或 `block_all`（暂停所有请求） |

几条行为值得先知道：

- **两个维度各自判定**，token 或金额任一过限都拦。金额上限只在价格表可用时生效，没填价格时报告会直说「金额上限未生效」。
- **月是自然月**，按每条记录写入时的当地日期归属，不看时区换算后的绝对区间。
- **前台的一轮总能走完**：用户正等着一个完整答复，半途报「到上限了」比多花这一轮更糟。下一轮开始前才判。
- **后台轮次在每次模型请求前重新判**，一轮工具循环中途到限就停；这一停算「这一拍已经过去」——心跳不会马上重试，定时任务也不会在额度恢复后把同一件事再做一遍。
- **账本读不出来时不拦**：扫描失败期间一律放行，重试最早在距上次扫描 30 秒之后、由下一次预算判定或状态查询触发，整月重扫成功才恢复拦截，期间在状态里标「不可用」——限额失效不该把人关在自己的程序外面。**启动时** `usage.json` 读不出有效值也一样：这次运行按默认值（不设限）跑；之后刷新用量页只会清掉「不可用」标记，**限额不会生效**——要在页面上保存一次或重启服务，新的上限才开始拦。
- **运行中把 `usage.json` 改坏是另一回事**：报表会报「设置读不出来」并提示仍是旧值，但运行中的限额照旧按上次加载的那一份拦，只有保存一次或重启才会换成文件里的内容（重启后文件仍然无效，就退回不设限）。
- 坏分片与写失败不退让：能读的照常算、照常拦。坏分片 `wen usage` 也看得到（「有 N 个分片读不出来」）；写失败只有运行中的服务能报告，从磁盘重新统计的报告看不出来。
- 设置在设置页保存后立即生效。手工改 `usage.json` 也能读，但运行中的那份预算不会跟着变，页面会提示「仍是旧值，点保存或重启后生效」。文件里的键名是严格的，拼错会报错而不是被忽略；版本比程序新时拒绝覆盖。
- 到限不会自动放开。`block_all` 切到 `skip_background` 只恢复前台，后台照样停；要恢复后台得调高或取消已触发的上限，或等下一个自然月。

## 三处查看

- **网页**：设置页 → 用量。按月选择，顶部是请求数、token、缓存命中率与估算金额，下面是按日的柱状图、按来源与按模型的明细，未定价与读不出的分片都会单独标出；预算设置在同一页。
- **命令行**：`wen usage`，默认看本月；`--days N` 改成最近 N 天，`--by` 换分组（天、来源、模型、类型、提供商、提供商与模型）。它直接读账本文件，服务在跑也照读。`wen status` 里也有一行本月用量与预算。见[命令行](cli.md#wen-usage查看本月用量)。
- **接口**：`GET /api/usage?month=YYYY-MM` 与 `PUT /api/usage/settings`，见 [HTTP API](http-api.md)。
